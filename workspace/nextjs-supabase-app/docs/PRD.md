# 모임 이벤트 관리 MVP PRD

## 🎯 핵심 정보

**목적**: 모임 주최자가 공지, 참여자 관리, 카풀, 정산을 흩어진 카톡/엑셀 없이 한 곳에서 처리하게 한다.
**사용자**: 수영/헬스 같은 정기 모임과 친구 모임 같은 비정기 모임을 운영하는 주최자 및 그 참여자.

## 📌 배경

기존 `nextjs-supabase-app` 저장소(Next.js 15 App Router + Supabase Auth 스타터킷)에 이어서 개발하는 신규 기능이다. 별도 프로젝트가 아니며, 기존 인증 플로우(`app/auth/*`, `app/protected/*`, proxy 세션 체크)를 그대로 활용한다.

## 🚶 사용자 시나리오

### 시나리오 1: 정기 모임 (수영 강습)

1. 주최자가 로그인 후 이벤트 생성 페이지에서 "화요일 저녁 수영 강습" 이벤트를 만든다.
2. 같은 일정을 여러 번 반복해야 하면, 주최자가 매주 동일한 내용으로 이벤트를 다시 생성한다(반복 규칙 자동화 없음).
3. 고정 멤버들이 각 회차 이벤트에 참여 신청을 한다.
4. 정원 초과 시 신청자는 대기자로 등록되고, 기존 참여자가 취소하면 대기자가 자동으로 승격된다.
5. 모임 종료 후 주최자가 정산 항목(강습비 등)을 만들면 참여자 수만큼 1/N 금액이 계산된다.
6. 참여자가 실제로 입금하면 주최자가 해당 참여자의 정산 상태를 "완료"로 표시한다.

### 시나리오 2: 비정기 모임 (친구 모임 + 카풀)

1. 주최자가 "이번 주말 캠핑" 이벤트를 1회성으로 생성하고 공지사항(집합 장소, 준비물)을 작성한다.
2. 참여자들이 참여 신청을 한다.
3. 차량이 있는 참여자가 카풀 운전자로 등록(좌석 수, 출발지, 출발 시간)한다.
4. 다른 참여자가 카풀 탑승을 신청하면 운전자 또는 주최자가 매칭을 확정한다.
5. 모임 후 주최자가 정산(캠핑장 비용, 식비 등 항목별)을 등록하면 참여자별 분담액이 계산되고, 입금 여부를 개별 체크한다.

## ⚡ 기능 요구사항

### F001. 이벤트 생성/관리

- **설명**: 주최자가 이벤트(모임)를 생성, 수정, 삭제하고 공지사항을 작성한다.
- **필드**: 제목, 설명/공지사항, 일시, 장소, 정원(최대 인원), 상태(모집중/마감/종료)
- **정기 모임 처리**: 별도 반복 규칙(occurrence) 없이, 주최자가 매 회차마다 이벤트를 새로 생성하는 방식으로 단순화한다.
- **권한**: 이벤트는 주최자(생성자)만 수정/삭제 가능. 모든 로그인 사용자는 이벤트 목록 조회 및 생성 가능.
- **관련 페이지**: 이벤트 목록 페이지, 이벤트 생성 페이지, 이벤트 상세 페이지

### F002. 참여자 관리

- **설명**: 참여 신청/취소, 참석자 목록 확인, 정원 초과 시 대기자 처리.
- **동작 규칙**:
  - 참여 신청 시 현재 참여 인원이 정원 미만이면 "확정" 상태로 등록.
  - 정원이 찬 경우 "대기" 상태로 등록.
  - 확정 참여자가 취소하면, 대기자 중 신청 순서가 가장 빠른 사람이 자동으로 "확정"으로 승격.
  - 주최자는 참여자 목록에서 상태(확정/대기/취소)를 확인하고 강제 취소 처리 가능.
- **관련 페이지**: 이벤트 상세 페이지(참여자 탭)

### F003. 카풀 관리

- **설명**: 운전자가 좌석 수와 출발지/시간을 등록하고, 탑승자가 신청하면 매칭한다.
- **동작 규칙**:
  - 참여자(확정 상태)는 운전자로 등록 가능(좌석 수, 출발지, 출발 시간 입력).
  - 다른 참여자는 등록된 카풀 중 하나를 선택해 탑승 신청.
  - 탑승 신청은 잔여 좌석 범위 내에서만 가능하며, 좌석이 차면 신청 불가(대기열 없음, MVP 범위 밖).
  - 운전자 또는 주최자가 탑승 신청을 확정/거절할 수 있다.
- **관련 페이지**: 이벤트 상세 페이지(카풀 탭)

### F004. 정산

- **설명**: 이벤트 비용을 참여자 수로 나눈 1/N 금액을 계산하고, 참여자별 완료 여부만 기록한다.
- **동작 규칙**:
  - 주최자가 정산 항목(예: "강습비", "캠핑장 비용")을 생성하고 총액을 입력.
  - 시스템이 정산 대상 참여자(확정 상태) 수로 총액을 나눠 1인당 분담액을 자동 계산.
  - 각 참여자별로 "입금 완료 / 미완료" 상태만 주최자가 체크.
  - 실제 결제/송금 연동은 하지 않는다(계좌번호 안내 등 수동 처리 전제).
- **관련 페이지**: 이벤트 상세 페이지(정산 탭)

### F005. 기본 인증 (기존 기능 재사용)

- 기존 스타터킷의 회원가입/로그인/로그아웃 그대로 사용. 신규 개발 범위 아님.
- **관련 페이지**: 로그인 페이지, 회원가입 페이지 (기존 `app/auth/*`)

## 🚫 MVP 범위 제외 (Non-goals)

- **실제 결제/송금 연동**: PG사 연동, 계좌이체 자동 확인 없음. 정산은 금액 계산과 완료 체크리스트로 한정.
- **occurrence 기반 정기 일정 관리**: 반복 규칙(RRULE 등)을 통한 자동 회차 생성 없음. 정기 모임은 매번 개별 이벤트로 수동 생성.
- **카풀 대기열/자동 매칭 알고리즘**: 좌석 초과 시 대기자 개념 없음(참여자 대기자 처리와는 별개).
- **알림/리마인더**: 이메일·푸시·문자 알림 없음.
- **프로필 상세 관리**: 아바타, 자기소개 등 확장 프로필 없음(`auth.users` 기본 정보만 사용).
- **모바일 앱**: 반응형 웹으로만 제공.

| 필드 | 설명 | 타입/관계 |

## 🛠️ 기술 스펙 요약

- **베이스**: 기존 저장소(Next.js 15 App Router + Supabase Auth 스타터킷) 위에 이어서 개발
- **라우트 구조**: `app/protected/events/` (목록) → `app/protected/events/new` (생성) → `app/protected/events/[eventId]` (상세, 참여자/카풀/정산 하위 탭)
- **데이터 조회**: 서버 컴포넌트 + `lib/supabase/server.ts`
- **폼 제출**: Server Actions (React Hook Form + Zod로 클라이언트 검증 후 서버 액션에서 재검증)
- **DB**: `events`, `participants`, `carpools`, `carpool_passengers`, `settlements`, `settlement_shares` 6개 테이블, 전 테이블 RLS
- **정기 모임 처리**: occurrence 테이블 없이 반복 생성되는 개별 `events` row로 단순 처리
- **신규 shadcn 컴포넌트**: form, dialog, select, table, tabs, textarea, avatar, calendar, popover, alert-dialog
- **신규 npm 패키지**: react-hook-form, zod, @hookform/resolvers, date-fns
- **상태관리**: zustand 도입하지 않음(서버 컴포넌트 + Server Actions로 충분)
